# RoCo 对接 RoboPARA 状态输入规划评测

## 变更摘要

- 在当前 `dev` 新增 `run_robopara_dialog.py`，通过本地 HTTP 运行逐轮联合动作，保留原多代理讨论、历史和失败重规划。
- 新增不依赖 MuJoCo 的状态提示、语义解析、反馈和客户端；交接合并成一个双臂技能，执行请求不自动重试。

- 支持单代理、无显式反馈、无历史开关及多种子运行；新增运行说明与针对本次新增测试、日志的 Git 忽略例外。

- 当前 `roco` 环境缺少 `google-genai`；本次使用已有 `roco39`，未修改依赖环境。
- 仿真接口不支持原路径点及执行前 IK／碰撞反馈；结果属于状态输入、共享技能执行器的适配版。
- 完整 HTTP 仿真服务启动权限请求被拒绝，本次未调用真实模型，未完成完整任务或多种子评测。
- 无反馈对照仍观察真实状态，但不接收显式执行诊断提示；平台仍执行强制合法性检查。

## 补充：限制重复规划和等待

- 仿真入口默认最多 12 轮、每次讨论 2 次发言、每轮 2 次规划尝试，连续规划或执行失败 2 轮即停止。
- 新增回合总请求预算 30 次、总耗时 600 秒、单次模型请求 60 秒；错误和超时请求计入预算。
- 有预算的入口禁用应用层及 SDK 自动 API 重试，避免多层重试放大调用次数。
- 使用 Linux 主线程定时信号中断阻塞等待；结束后关闭会话最多等待 5 秒，保留关闭错误。
- 修复奇数发言上限可能超出一次的问题；独立图片规划入口也加入总请求和耗时预算。
- 汇总日志记录停止原因、预算、实际请求数、响应数和异常；原 MuJoCo 入口未配置预算时保留原重试设置。
